# Slice 2: the data layer, `decadra now`, and `decadra assess`

## Scope decision (agreed this session)

Decadra is the money meter for agent sessions. From any shell or any agent's `!` prompt it tells you what you have spent per provider, in that provider's own unit, against the plan you hold, and once a month which tier fits. Offline, read-only, never ranking providers.

Consequences:

- `decadra now` is the primary surface and ships in this slice with `assess`, on one shared data layer. When Decadra detects it is running inside an agent session, bare `decadra` prints `now` instead of the home screen. The home screen remains the no-argument splash on a bare terminal only.
- A total of subscription prices from the baseline is allowed: it is money paid, not consumption. Usage, tokens, and units stay per provider and are never summed. This carve-out is written into `AGENTS.md` and into the guard test as an explicit allowance keyed on the word "bill".
- Integration beyond the manual `!` call is out of scope for now. `--json` exists on every command already; a status line form can come later.
- No charts, no TUI dashboard, no live quota polling with vendor credentials, no provider count race.

### `decadra now`

Purpose: a readout that fits in a pane, returns in well under a second on a normal history, and reads correctly both to a person and to the agent that will see it (since Claude Code 2.1.186, `!` output is shown to Claude by default).

Detection (`src/ui/agent-env.ts`, pure over `process.env` and cwd):

| Agent | Signal | Current session |
|---|---|---|
| Claude Code | `CLAUDECODE=1`, `AI_AGENT` starts with `claude-code_` | newest `*.jsonl` at depth one in `~/.claude/projects/<encoded cwd>/`, where the encoding replaces every character outside `[A-Za-z0-9]` with `-`, and the file's own `cwd` field confirms the match |
| Codex | `CODEX_SANDBOX` or `CODEX_SANDBOX_NETWORK_DISABLED` present | newest `rollout-*.jsonl` whose `session_meta.cwd` equals cwd |
| Cursor CLI | `CURSOR_TRACE_ID` or `CURSOR_AGENT` present | newest transcript under `~/.cursor/projects/*/agent-transcripts/`, marked coarse |
| Muse Code | no known signal yet; `--provider meta-muse` forces it | newest `session.jsonl` for today |
| none | plain shell | `now --all` behaviour |

Output, one provider block (the detected one; `--all` for every provider in alphabetical order):

```
Claude  (anthropic-claude-code)   held: Max 20x $200/mo   as of 2026-09-05
  this session   $3.41 list-equivalent   47 min   12 turns
  today          $18.20                  month to date $412.50 (2.1x plan price)
  pace           $540 by month end at this rate (5 of 30 days observed)
  ceiling        no recorded utilization; set an anchor for an estimate
  last verdict   hold, medium confidence, 2026-09-01
  readout only: consumption at list prices, not value; per provider, never across providers.
```

Data per block: session cost from `ccusage <source> session --json` filtered to the detected session id (Claude, Codex) or from the native reader once it exists; today and month to date from `ccusage <source> daily --json --since <month start>`; pace as month-to-date divided by days observed times days in month; ceiling from recorded utilization where the tool writes it, else the anchor estimate, else the prompt to set one; last verdict from `verdicts.jsonl`. Cursor and Devin blocks show included credit remaining and ACUs burned from imports or manual entries once those exist; until then the block says so.

Header line when `--all` and a baseline exists: `You pay $220/month across 2 subscriptions (baseline 2026-09-05).` This is the only cross-provider figure anywhere, and it is a sum of prices.

Timing: `now` prints its own elapsed time in `--json` and behind `--timing`. If ccusage takes over about a second on a real history, the follow-up is a cache of closed days under `~/.decadra/cache/daily/<provider>/<YYYY-MM-DD>.json` so only today is recomputed. Not built until measured.

Exit code 0 always, so a `!decadra now` never reads as a failure to the agent.

## Design

### Window and months (`src/analysis/months.ts`, pure)

- `--months N` (default 3): the N most recent calendar months including the current one. `since` is the first day of the month N-1 months back, `until` is today, both UTC dates. `--since` and `--until` override and are passed through as `YYYYMMDD` to ccusage.
- `bucketMonths(dailyRows, since, until, today)` returns one `MonthlyUsage` per calendar month in the range, including months with no rows (amount 0, so a quiet month counts as quiet rather than vanishing). `daysObserved` is the number of days of that month inside `[since, min(until, today)]`; `daysInMonth` is the calendar length. Proration lives in `planfit.prorate`.
- ccusage buckets `date` in UTC because we pass `--timezone UTC`; the month bucketing uses the same string prefix, so no timezone math.

### Windows (`src/analysis/windows.ts`, pure)

- `rollingSums(daily, days = 7)`: for every day in the range, the sum of `totalCost` over that day and the six before it, with missing days as 0. Returns the series.
- `percentiles(values)`: p50, p95, max with nearest-rank.
- `weeklyPeak(daily)`: `WindowPeak { kind: 'weekly', max, p95 }` from the rolling series. Empty input yields no peak rather than zeros.
- `shortPeak(blocks)`: `WindowPeak { kind: 'short', ... }` from block `costUSD`, skipping `isGap`. Only Claude has blocks in ccusage; other sources have no short peak until a native reader supplies timestamps.

### ccusage runs (`src/ingest/ccusage.ts`, extend)

- `CcusageRunner = (inv: CcusageInvocation) => Promise<unknown>`; the real one is `runCcusage`, tests pass a fake that returns fixture JSON. `assess` takes the runner through its options so nothing is spawned in tests.
- `writeCcusageConfig(paths, plans)`: writes `~/.decadra/cache/ccusage.json` with `{ defaults: { pricingOverrides } }`. One override per `modelPricing` entry whose four values are all non-null, keys `inputCostPerToken`, `outputCostPerToken`, `cacheCreationInputTokenCost`, `cacheReadInputTokenCost`, values per token (per million divided by 1e6). Entries with any null are skipped and named in a note. Overrides apply even when ccusage's own table prices the model, so the user's numbers win when set; that is intentional and stated in the plans.json comment.
- `fetchDaily(runner, source, since, until, configPath)` and `fetchBlocks(...)` parse with the schemas and throw a typed `CcusageError` naming the source and the exact argument list on failure.

### Held plan timeline (`src/store/baseline.ts`, extend)

- `heldPlanOn(records, provider, date)`: latest non-superseded record for the provider with `asOf <= date`, or null.
- `heldPlanChanges(records, provider, since, until)`: the distinct tiers held across the window, in order. When more than one, the section gets a note listing them and the verdict's `heldPlan` is the one held today. Usage itself is not split by plan; the plan only changes the "held" row and the Codex scaling later.

### The command (`src/commands/assess.ts`)

For each adapter from `resolveAdapters(plans)`:

- `usage.kind === 'ccusage'`: fetch daily (and blocks for `claude`), bucket months, compute peaks, read anchors from the provider's plans entry, call `assessPlanFit`, collect `zeroPricedModels(daily)`.
- Any other kind: no usage. Build the section with the plan table showing price only, a note "no usage data for this provider yet: <import in 0.4.0 | native reader in 0.4.0 | manual entry in 0.4.0>", and a verdict with direction `unknown` and `monthsOfEvidence` 0. Absence stays visible.
- A ccusage failure for one provider becomes that provider's section with a `note` carrying the error and marks the run exit code 1 at the end. Other providers still render.

Section shape (`data`, strict per-command zod schema in `src/commands/assess.schema.ts`): `{ meter, source: 'ccusage' | 'none', window, months, windowPeaks, rows, verdict, zeroPricedModels, heldPlanChanges, error }`.

Blocks: `kv` (held plan, median usage, months of evidence, plan changes), `table` (plan, price, effective per month, multiple or blank, ceiling column: `fits`, `above est.`, `no evidence`, or `n/a` for uncapped), `line` from `planFitLine(section)`, `note` for zero-priced models naming the `modelPricing` key, `note` for skipped overrides.

Caveats on the report: `CAVEATS.listPrice`, `CAVEATS.ceilingEstimate`, `CAVEATS.perProvider`.

Output: `renderReport(report, ctx.format)`. `--html <file>` writes the html string to the file and prints the path; the placeholder html write in `cli.ts` goes away. Every run appends `{ ts, window, verdict }` per provider to `~/.decadra/verdicts.jsonl` through `src/store/verdicts.ts` so history accrues for slice 6.

### Doctor (`src/commands/doctor.ts`, extend)

New check per ccusage provider: run daily for the last 30 days and fail on any zero-priced model, naming it and the `modelPricing` key to fill. Also warn when a `modelPricing` entry has a null field, since the override for that model is skipped entirely.

### CLI (`src/cli.ts`)

Replace the planned stub for `assess` with real options: `--months <n>` (default 3), `--since <date>`, `--until <date>`, `--provider <id>` (repeatable filter). Keep the other stubs.

### Review findings folded in (verified against the bundled ccusage binary)

Layer placement:
- `src/analysis/months.ts` and `windows.ts` receive plain arrays (`{date, cost}`, `{costUSD, isGap, entries, isActive}`), never raw ccusage JSON. The lint fence on `src/analysis` stays intact.
- The ccusage config write lives in `src/ingest/ccusage-config.ts`, exported as `writeCcusageConfig(paths, modelPricing)` so tests read it back.
- Section `data` types and their strict zod schemas live in `src/commands/*.schema.ts`; `src/report` stays generic.
- The doctor zero-price check runs from `collectChecks`, since it needs `modelPricing` and the runner; adapters only see `DoctorEnv`.
- Render baseline `product` and price on separate kv rows so a free-text product name never shares a line with an amount.

Months:
- The month list comes from the calendar `[since, until]`, never from ccusage rows, which omit empty days and return `[]` for an empty range. All date arithmetic in `Date.UTC`.
- `daysObserved`: first month `daysInMonth - since.day + 1`, last month `min(until, todayUTC).day`, middle months full. `--until` is clamped to today; `--since` after `--until` is a `CliError`.
- Months with fewer than 7 observed days are shown as "partial, excluded" and dropped before `assessPlanFit`, so a 5-day month prorated 6x cannot carry a full month's weight in the median. `minDaysForEvidence` is a `PlanFitInput` field with default 7.
- Local data start: `ScanResult` gains `oldest`; the adapter exposes the oldest session-file date; months that end before it are excluded with the evidence line "local data begins YYYY-MM-DD; N month(s) of the window have no transcripts on disk". This is what stops Claude Code's 30-day transcript pruning from reading as two quiet months and a downgrade at high confidence. Codex does not prune, so month counts will differ per provider, and the output says so.

Windows:
- Rolling 7-day sums over a dense zero-filled day array, windows fully inside the range; under 7 days, one window. Labelled "day-aligned" because a burst across midnight splits, and because Anthropic's weekly cycle is fixed from first use rather than rolling.
- Weekly peaks only when the provider's `windows` has a weekly entry effective in the range; short peaks only for sources with blocks (Claude). Codex gets `anchors.short = null`.
- Blocks: pass the plan's short window hours to ccusage as its session length (`buildCcusageArgs` gains `sessionLengthHours`), skip `isGap` and `entries === 0`, keep the active block but label it as partial in the note. When p95 equals max because there are few blocks, say so.
- `WindowPeak` gains optional `p50` for display only.

Held plan:
- `heldOn(records, provider, date)`: non-superseded, `asOf <= date`, latest `asOf`, tie by `recordedAt`. The plan for the verdict is the one held on the window's `until`, not today. `currentByProvider` is not reused because it ignores `asOf`.
- A baseline `tier` that no longer exists in `plans.json` is reported as such, not treated as no plan.
- `heldByMonth` on `PlanFitInput`, used only for evidence text and a "what you paid" figure (`monthlyUsd × daysHeld / daysInMonth` summed), never for `best`.

Pricing through ccusage:
- Always `--mode calculate` so cost is list price from tokens even where old transcripts carry a `costUSD`. The args test asserts it alongside `--offline --timezone UTC`.
- `modelPricing.cacheWrite` is the 5-minute cache write price. ccusage prices 1-hour cache writes at twice `inputCostPerToken`, so an override missing `input` silently prices 1-hour writes at zero; the all-four rule is a correctness requirement and the schema comment says why. Decadra never re-prices `cacheCreationTokens` from daily JSON because that figure blends two rates.
- The long-context override fields are set explicitly equal to the base prices so results are deterministic; documented in the plans.json comment.
- ccusage may still merge a user's own discovered config with `--config`; `doctor` prints the exact command line and notes the three discovered-config paths so a surprise can be traced.

Schemas:
- `dailyRow` and `sessionRow` accept `totalCost` or `costUSD`, and `modelBreakdowns` or a `models` array; `src/ingest/usage.ts` normalizes so provider quirks stop at ingest. Slice 2 is not done until a redacted non-empty Codex fixture captured on the laptop parses.

Verdicts and templates:
- `verdicts.jsonl` records `{ recordedAt, window, plansAsOf, ...verdict }` with a zod schema, so slice 6 can apply consecutive-month and minimum-days rules and filter custom windows.
- `planFitLine` branches on `heldPlan === null` ("no baseline snapshot for this provider; record one with decadra baseline add") instead of "not enough data", and the verdict carries display names alongside ids.
- Providers without usage skip `assessPlanFit` entirely and get a direct `unknown` verdict with zero months, so no row shows a `0x` multiple.

Command plumbing:
- Deps seam: `runAssess(ctx, opts, deps = defaultDeps(ctx))` and the same for `now`, where `deps = { runCcusage, now: () => Date }`. Tests build a `CommandContext` over a temp dir, seed the baseline with `addBaseline`, and pass a runner keyed on `${source}-${report}` that records invocations so they can assert `--offline`, `--mode calculate`, and the config path under `cache/`.
- `--html` for `assess` writes the file itself and prints the path; terminal output is suppressed in that mode. The placeholder write in `cli.ts` is removed.
- `--provider <id>` with an unknown id is a `CliError`. Exit code 2 stays reserved for planned commands.
- Never assert equality between daily sums and block sums; both read live files and differ slightly during an active session.
- Laptop check before trusting the no-network claim for Codex: run `ccusage codex daily --offline` once with networking off.

### Shared data layer (`src/ingest/usage.ts`)

One function both commands call: `loadProviderUsage(adapter, range, deps)` returning `{ daily, blocks?, sessions?, zeroPricedModels, source }` for ccusage-backed adapters and `{ source: 'none' }` for the rest. `deps` carries the ccusage runner, the config path, and the clock, so tests inject fixtures and a fixed today. `now` asks for the current month; `assess` asks for the window.
